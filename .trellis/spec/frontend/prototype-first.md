# 原型优先 UI 开发契约

## 适用范围与决定

适用于全部 Android UI：页面、导航、弹窗、底部面板、共享组件、状态反馈与可见交互。用户在本次 `10-01-ui-polish` 规划中明确确认：**以 `prototypes/nastools-ui/` Concept 01 为基准；没有原型的 UI 必须先做原型。**

这是已确认的开发约定，不表示 Android 已完成迁移，也不表示原型里的演示能力全部批准为新功能。

阅读入口：`prototypes/nastools-ui/BASELINE.md` → 对应任务 PRD / `research.md` → 已确认原型场景 → 本规范、`design-tokens.md`、`state-feedback.md`。

## 1. 权威边界

- 已确认原型决定视觉与交互意图：配色、层级、结构、组件和操作路径。
- 真实业务契约决定数据和操作后果。模拟原型不能覆盖上传冲突、安全删除、认证、系统权限、后台任务等行为。
- Android 安全区域、返回、权限弹窗、系统选择器、无障碍优先；显著布局/流程偏差必须说明并经用户确认。
- 不移植桌面设计说明、手机外框、模拟状态栏、重置演示按钮、样例素材或模拟成功逻辑。
- 原型和既有功能冲突时先补原型，不得任意二选一或默默删掉功能。

## 2. 强制变更流程

1. 列出受影响页面、组件、交互和状态，找到可操作的已确认原型入口。
2. 对照现有代码区分：已有能力、原型漏项、原型新增能力、原生差异。
3. 缺少任何必要 UI 时先补原型；已有基准的修改需记录改了什么。
4. 用户明确确认新增/修改的原型范围，记录在基准或任务决策记录中。
5. 才能实现 Compose；执行任务仍需通过 Trellis 规划评审与启动门槛。
6. 对照截图与真实交互验收；变更原型及实现时同步更新状态表与规范。

只批准「开始规划」不等于批准未见过的原型补充，也不等于批准正式实现。禁止开发完成后再倒补原型作为形式手续。

## 3. 基准与版本记录

- `prototypes/nastools-ui/BASELINE.md` 保存 Concept 标识、来源文件、确认范围、待补项、文件摘要及后续确认记录。
- 原型/CSS/JS/本地资源必须纳入 Git。未提交时记录文件 SHA-256，提交后记录实际基准 commit；不得虚构版本。
- 修改原型即产生待确认差异。不能因为目录名不变就沿用旧确认；用户已批准的未修改部分仍有效。
- 截图只是证据，HTML + CSS + JS 的已确认场景才是基准；手机展示外框不属于应用验收区域。

## 4. 每项 UI 的交付记录

任务 `research.md` / 验收表必须包含以下字段，可一项一行：

| 字段 | 内容 |
|---|---|
| UI 标识 | 页面/组件 + 场景名，例如 Browser / 刷新失败但有旧内容 |
| 原型入口 | 文件与操作路径，不能只写「参考原型」 |
| 功能归属 | 已有能力 / 本任务新增 / 其他任务 / 演示专用 |
| 确认状态 | 待补 / 待确认 / 已确认，并记录确认依据 |
| Android 映射 | 对应 Screen、组件、ViewModel/状态来源 |
| 状态覆盖 | 正常、加载、空、错误、禁用、进行中、确认等 |
| 平台偏差 | 无 / 明确理由与审批依据 |
| 验收证据 | 同场景明暗截图、交互检查、未完成原因 |

例：Browser 刷新失败有旧文件 → 原型补充该状态并确认 → 复用 `BrowserUiState.shouldShowBlockingError()` → 旧内容保留 + Snackbar；不能照搬原型演示错误按钮将整个文件列表替换成错误页。

## 5. 完整状态与保留功能

- 页面：初次加载、内容、无数据、无搜索结果、错误/重试、刷新有旧内容。
- 操作：可用/禁用、执行中、防重复点击、成功/失败、选择/取消选择。
- 危险操作：说明真实影响，确认只执行一次；取消不得执行；沿用 `state-feedback.md`。
- 媒体：加载、切换、解码/网络失败、重试、不可预览文件。
- 任务：waiting/running/paused/completed/failed/cancelled；未知总量、跳过汇总、失败详情不可遗漏。
- 既有功能即使原型未画也必须保留。文件夹上传、移动上传、文件夹冲突、批量任务删除等先补原型再迁移。
- 原型新增但未批准/未实现的按钮不进入正式版本；不得保留可点击却只给假成功的入口。

## 6. Token 与组件

- 继续使用 `presentation/theme/` 与 `presentation/components/`，不新增平行主题。
- CSS 角色先映射到 Compose 语义角色，再集中调整值；禁止每个页面直接复制十六进制颜色和局部阴影。
- 原型确认后的值变更替代旧视觉值，但不替代业务状态语义。
- px 不能机械等同 dp/sp。系统字体、48dp 热区、字体缩放与 insets 必须兼容；例如 40px 图标按钮可保留视觉尺寸但扩展触摸区域。
- 局部偏差要记录，不能以「原生适配」为由自行重设计。

## 7. 验收门槛

- 同页面、同数据、同状态，浅色/深色各一组 Compose 预览和运行截图；关键 UI 与原型应用区域并排检查。
- 至少验证 320dp、390dp 和更宽窗口；字体 1.0 与 1.3/2.0；长文件名、多级路径、键盘展开、系统返回和安全区域。
- 可访问名称、可读对比度、48dp 热区、非颜色状态提示、减弱动画；Web 原型支持键盘焦点和 reduced motion。
- 检查共享组件改动的所有调用方，不只截图当前页面。
- 执行编译/单测/lint；用真实或受控测试服务回归网络及上传流程。原型冒烟测试不能替代 Android 测试。
- 无设备/依赖下载失败时记录「未验证/阻塞」，不得声称视觉或发布验收完成。

## 错误与正确做法

| 错误 | 正确 |
|---|---|
| 原型没有移动上传，于是删掉开关 | 补移动上传原型、风险提示与确认，再迁移既有能力 |
| 原型写了“测试成功”，正式按钮直接显示同样文案 | 调用真实连接测试，根据结果展示成功/错误 |
| 每页复制 `#245c48` | 映射为主题 accent / M3 primary，从统一 token 读取 |
| 原型新增重命名，所以直接调用 MOVE | 先确认范围，设计同名保护、路径校验、失败与刷新契约 |
| 只编译通过就标记 UI 完成 | 明暗截图、完整状态、设备交互检查及用户目视验收 |
